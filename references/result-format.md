# result.md 형식

실행 1회 = `result.md` 1개. `runs/<순번>-<라벨>/result.md` 에 쓴다.

## 템플릿

```markdown
# <작업 요약> — 001-<라벨>

## 실행
| 항목 | 값 |
|---|---|
| 시각 | 2026-09-15 16:20 ~ 16:25 |
| 기기 | S25 `R3CXXXXXXXX` (Android 16 / One UI 8.5) |
| 빌드 | 구버전 = debug · 신버전 = release(minify) |
| 시나리오 | `scenario.md` (수정 2026-09-15 16:05) |
| 근거 자료 | Crashlytics `a1b2c3d4` 스택 — 사용자 제출 2026-09-15 |
| 로그 | `run.log` |

## 판정
| # | 시나리오 | 결과 | 근거 |
|---|---|---|---|
| 1 | 알림 콜드스타트 task 재실행 | PASS | 크래시 1건 · 스택 `SplashActivity.kt:48` |
| 2 | 설정 이동 없이 업데이트 | 실행불가 | 사전조건 미충족 — recents 카드가 숨겨짐 |

PASS <n> / FAIL <n> / 실행불가 <n>

## 실패 상세
### 시나리오 2 · 스텝 7
- 결함: 시나리오·스크립트 결함
- 관찰: `6-1. recents MyApp 카드: 없음`
- 캡처: `fail-01.png` · `fail-01.xml`
- 근거: One UI 가 activity 없는 task 카드를 숨긴다. 앱 동작이 아니라 시나리오 전제가 틀렸다.

## 다음
- 시나리오 2 의 사전조건에 "설정 앱이 task 위에 있을 것" 을 추가하고 재실행한다.
```

## 규칙

- `## 실행` 의 `근거 자료` 행은 `scenario.md` 의 `근거 자료` 를 그대로 옮긴다.
- `## 판정` 의 `근거` 칸에는 로그 원문을 인용한다. 요약하지 않는다.
- 실패가 없으면 `실패 상세` 절을 통째로 지운다.
- `결함` 은 둘 중 하나로만 쓴다 — `앱 버그` · `시나리오·스크립트 결함`. 판단이 안 서면 `미결: <질문> / 답할 사람: 사용자` 로 남긴다.
- 앱 버그를 고치지 않는다. `다음` 에 무엇을 보고했는지만 쓴다.
- 배경 설명·총평을 쓰지 않는다.
