# summary.md · failures.md 형식

작업 폴더에 하나씩 둔다. 작업 전체의 최종 결론이다. run 의 `result.md` 는 실행 직후 판정만 담는다.

## summary.md

agent 가 5단계마다 갱신한다.

```markdown
# DCL-1538 온보딩

## 최종 판정
| # | 시나리오 | 판정 | 근거 run | 근거 |
|---|---|---|---|---|
| 1 | 첫 실행 온보딩 진입 | PASS | 005 | `PASS  1.3 온보딩 1단계 노출` |
| 2 | 단계 저장 | PASS | 005 | `PASS  2.4 단계 조회 응답 step=2` |
| 8 | 종료 안내 | FAIL | 004 · 006 | F05 |
| 10 | 재진입 | 미결 | 004 | F07 |
| 11 | 완료 후 메인 | 실행불가 | 006 | 의존 S08 FAIL |

## run 목록
| run | 범위 | 결말 | 재실행 사유 |
|---|---|---|---|
| 001 | S01-S12 | 중단@S01.2 | — |
| 002 | S01-S12 | 중단@S01.4 | F01 스크립트 결함 |
| 003 | S01-S12 | 중단@S02.1 | F02 스크립트 결함 |
| 004 | S02-S12 | FAIL-1_중단@S10.3 | F03 스크립트 결함 |
| 005 | S01-S07 | 완료 | F06 사람 진행 오류 |
| 006 | S08-S12 | FAIL-1_실행불가-1 | F05 앱 버그 재확인 |
```

| 칸 | 값 |
|---|---|
| 판정 | `PASS` · `FAIL` · `실행불가` · `미결` |
| 근거 run | 판정을 낸 run 번호. 여러 run 이 같은 결과면 `·` 로 잇는다 |
| 근거 | `PASS` 는 판정 원문 줄. `실행불가` 는 사유. 그 외는 `failures.md` ID |
| 범위 | run 폴더 이름의 `S<시작>-S<끝>` |
| 결말 | run 폴더 이름의 접미사(`TD_SUFFIX`) |
| 재실행 사유 | 이 run 을 만든 `failures.md` ID 와 분류. 첫 run 은 `—` |

- `FAIL` 은 `앱 버그` 로 분류된 실패만 쓴다.
- `스크립트 결함` · `기준 결함` · `사람 진행 오류` 로 난 실패는 고친 뒤 재실행한 run 의 결과로 판정한다.
- 재실행하지 않은 시나리오는 마지막 run 의 판정을 쓴다.

## failures.md

`td_require_env` 가 머리행을 만들고 `td_capture_failure` 가 실패마다 행을 추가한다.

```markdown
| ID | run | 스텝 | 종류 | 분류 | 원인 | 조치 | 캡처 |
|---|---|---|---|---|---|---|---|
| F01 | 001 | S01.2 | step | 스크립트 결함 | 설치본 서명이 달라 `INSTALL_FAILED_UPDATE_INCOMPATIBLE` | 2단계 서명 비교 후 uninstall · 002 에서 확인 | runs/001_S01-S12_중단@S01.2/fail/S01.2_step.png |
| F05 | 004 | S08.4 | check | 앱 버그 | 종료 안내 노출 중 `GET /v1/onboarding/step` 호출 없음 | 보고 | runs/004_S02-S12_FAIL-1_중단@S10.3/fail/S08.4_check.png |
| F06 | 004 | S10.3 | human | 사람 진행 오류 | 안내 문구가 "뒤로가기" 와 "닫기" 를 구분하지 않았다 | 안내 문구 수정 · 005 에서 확인 | - |
```

| 칸 | 자동 값 | agent 가 채우는 값 |
|---|---|---|
| ID | 기존 `\| F` 행 수 + 1 (`F01`) | — |
| run | run 폴더 이름 앞 3자리 | — |
| 스텝 | SID (`S08.4`) | — |
| 종류 | `step` · `check` | `human` 행은 agent 가 추가한다 |
| 분류 | `미분류` | 결함 분류 6종 중 하나 |
| 원인 | 스텝 설명 | 원인 한 문장. 로그 원문을 인용한다 |
| 조치 | `-` | 고친 것 · 확인한 run. 앱 버그는 `보고` |
| 캡처 | `runs/<run 폴더>/fail/<SID>_<종류>.png` | `human` 행은 `-` |

- `td-finalize.sh` 가 run 폴더 이름을 바꾸면 캡처 경로도 바꾼다.
- `human` 행의 ID 는 마지막 ID + 1 이다.
- 분류가 바뀌면 이 행을 고친다. `result.md` 는 고치지 않는다.
- 행을 지우지 않는다.

## 결함 분류

| 분류 | 판정 근거 | 다음 |
|---|---|---|
| 앱 버그 | 스텝이 의도대로 실행됐고 앱 동작이 기준과 다르다 | 보고하고 멈춘다 |
| 스크립트 결함 | 좌표 · 문구 · 타이밍 · 감지 조건 · 사전조건 · 빌드 변형이 틀렸다 | `run.sh` 를 고쳐 재실행한다 |
| 기준 결함 | 판정식 또는 기대 동작 해석이 틀렸다 | `scenario.md` 를 고치고 사용자 확인 후 재실행한다 |
| 사람 진행 오류 | `[human]` 스텝을 다르게 수행했다 | 안내 문구를 고쳐 재실행한다 |
| 연쇄 | 앞선 실패의 여파다 | 원 실패 ID 를 원인 칸에 쓴다 |
| 미결 | 정책 확인이 필요하다 | `미결: <질문> / 답할 사람: <누구>` 로 남긴다 |
