# 서브에이전트 프롬프트

커스텀 에이전트 파일을 만들지 않는다. 템플릿의 `<>` 를 채워 내장 에이전트에 넘긴다.

## A1 코드 조사

| 항목 | 값 |
|---|---|
| 쓰는 곳 | 3단계 `scenario.md` 작성 전 |
| 에이전트 | `Explore` (Agent 도구 `subagent_type: "Explore"`) |
| 입력 | 변경 범위 · 검증 화면 · 플로우. 하나라도 비면 dispatch 하지 않고 사용자에게 묻는다 |

```text
Android 프로젝트 코드를 읽고 E2E 시나리오 작성에 필요한 사실을 표로 보고한다.

프로젝트 루트: <절대경로>
변경 범위: <커밋 SHA 범위 | 브랜치 이름 — 비교 기준 브랜치>
검증 화면: <화면 이름 목록>
플로우: <첫 실행 → … → 완료 한 줄>

제약
- 읽기 전용이다. 파일을 만들거나 수정하지 않는다.
- adb · gradle · 에뮬레이터를 실행하지 않는다. 기기를 조작하지 않는다.
- 코드에서 확인한 것만 쓴다. 확인하지 못한 값은 `미확인` 으로 쓴다.
- 모든 행에 근거 `경로:줄` 을 붙인다.

아래 네 절을 이 순서로 보고한다.

## 1. 화면 요소
| 화면 | 요소 | resource-id 또는 문구 | 경로:줄 |
- View 는 resource-id 를 쓴다.
- Compose 는 testTag · contentDescription · 표시 문구를 쓴다. testTag 가 resource-id 로 노출되는지(testTagsAsResourceId) 함께 쓴다.
- 문구는 기본 values/strings.xml 의 실제 값을 쓴다. 리소스 이름만 쓰지 않는다.

## 2. API
| 경로 | 호출 위치 | 로그 태그 |
- 로그 태그는 debug 빌드 logcat 에서 이 호출을 볼 수 있는 태그다. 없으면 `없음`.

## 3. 첫 실행 경로의 가로막는 화면
| 순서 | 화면 | 뜨는 조건 | 닫는 요소 | 경로:줄 |
- 클린 설치 → 실행 → 메인 도달 사이에 뜰 수 있는 화면을 모두 쓴다(권한 · 약관 · 업데이트 안내 · 로그인 · 온보딩 · 팝업).

## 4. debug 판정 수단
| 수단 | 있음/없음 | 상세 | 경로:줄 |
- 네트워크 로그 인터셉터 — 클래스 · 로그 태그 · 레벨 · 적용 빌드 타입
- WebView 디버깅 — setWebContentsDebuggingEnabled 호출 여부 · 조건
- SharedPreferences · DataStore — 파일 이름 · 암호화 여부(EncryptedSharedPreferences 등)
```

| 결과 절 | 쓰는 곳 |
|---|---|
| 1. 화면 요소 | `td_tap` · `td_wait_ui` 술어 · `[check]` 기준 |
| 2. API | `td_logcat_start` 인자 · 로그 구간 기준 |
| 3. 가로막는 화면 | 4a 사전 탐색에서 확인할 화면 목록 |
| 4. debug 판정 수단 | 기준에 쓸 판정 수단 선택 |

결과의 `경로:줄` 을 1개 이상 열어 대조한 뒤 쓴다.
